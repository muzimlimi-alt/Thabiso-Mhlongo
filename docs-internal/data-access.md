# Data Access Map — server.js / database.js

_Generated by automated static analysis (Phase 1 read-only recon). Repo: booking-system app. Source files analyzed: `server.js` (19261 lines), `database.js` (2625 lines)._

## Methodology and known limitations

- **SQL statement detection**: every call site of `db.get(`, `db.all(`, `db.run(`, `db.prepare(`, `db.exec(`, `db.each(`, and the promisified wrappers `dbRun(`, `dbGet(`, `dbAll(` (defined once around L3977-3985, wrapping the raw `db.*` calls — those 3 internal definition call sites are excluded from the count below since they are generic passthroughs, not distinct statements) was located via a hand-written balanced paren/string/template scanner (not naive regex), so multi-line template-literal SQL and nested parens/callbacks are handled correctly. The **starting line number reported is the line where the SQL argument (or, for dynamically-built queries, the variable's initial assignment) begins**, not the line of the `db.xxx(` token when they differ.
- **Dynamically built queries**: a handful of call sites pass a local variable (`sql`, `query`, etc.) built up in the same route via string concatenation (`sql += ...`) rather than a literal. For these, the tool walks backward to the variable's `const/let` assignment, concatenates any `+=` continuations found between that assignment and the call, and extracts table names from the combined text. This is a heuristic — conditionally-added fragments are all merged together regardless of which branch actually executes, so it may over-report tables for these specific statements. They are marked `via var` in the raw data; treat table lists for these rows as "possible", not "always".
- **Route attribution ("nearest preceding route registration")**: for each SQL statement, the enclosing route is taken to be the nearest `app.get/post/put/delete/patch(...)` registration whose line number is less than the statement's line number, scanning upward. This is a heuristic, requested as acceptable for this recon pass, and it has a specific, important failure mode in this codebase: **several SQL statements live inside shared top-level helper functions** (e.g. `logAudit()` L4028, `resolveActor()` L4014, `resolvePopiaTargets()` L4050, and others), which are defined once at module scope and *called from many different routes*. A naive nearest-route scan would misattribute all of their SQL to whichever route happens to be textually above the helper's definition, which is almost always wrong and would make true write fan-out look artificially low. To avoid silently under-counting, this tool separately detects when a statement sits inside such a top-level helper (any column-0 `function name(...)` or `const name = (...) =>` declaration) and instead reports it as `helper <name>() (~N call-sites in file)`, flagged `[indirect]`, rather than pretending it belongs to one route. **Tables written only through such helpers are called out explicitly in the "High write fan-out" section below** even though the static per-route write count may show ≤5 — the true fan-out is the helper's call-site count. A human reviewer should treat any `[indirect]` entry as "likely higher fan-out than shown."
- **Table extraction**: table names are read off `FROM`, `JOIN`, `INSERT INTO`, `UPDATE`, `DELETE FROM`, `REPLACE INTO` clauses via regex over the extracted SQL text. Comma-joined `FROM a, b` lists are split. Subquery table references are picked up because the scan is global over the whole statement text. The DML target table of an UPDATE/DELETE/INSERT is excluded from that same statement's "read" set even though it technically appears after `FROM`/is referenced, to avoid every write also double-counting as a read of the same table in the same statement (self-referential subqueries against the same table, e.g. `UPDATE bookings SET x=(SELECT y FROM bookings ...)`, are consequently not separately flagged as a read — a rare edge case).
- **72-table canonical list** comes from every `CREATE TABLE [IF NOT EXISTS]` statement in `database.js`.
- This is Phase 1 read-only reconnaissance. No files other than this one were created or modified.
